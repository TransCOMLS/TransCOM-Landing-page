# TransCOM — เว็บไซต์บริการแปลเอกสาร

เว็บไซต์สองภาษา (ไทย/อังกฤษ) สำหรับบริการแปลเอกสาร ลูกค้าดูบริการ ประเมินราคา และส่งงานได้จากมือถือ
ส่วนผู้ให้บริการจัดการทุกอย่างจาก Google Sheet ไฟล์เดียว ไม่ต้องเช่าเซิร์ฟเวอร์

| ส่วน | ใช้อะไร | หน้าที่ |
|---|---|---|
| หน้าเว็บ | GitHub Pages | ไฟล์ HTML/CSS/JS ในโฟลเดอร์นี้ |
| โดเมน | `www.prathaitranslation.com` (DNS ที่ Cloudflare) | ชี้มาที่ GitHub Pages (ข้อ 7) |
| ระบบหลังบ้าน | Google Apps Script (`apps-script/Code.gs`) | รับงาน, ติดตามสถานะออนไลน์, อีเมลแจ้งสถานะ, บัญชีลูกค้า, ข่าว/โปรโมชั่น, ลบข้อมูลตามกำหนด |
| ฐานข้อมูล | Google Sheet | ชีต Users, Jobs, Promotions, News + ภาพรวม (Dashboard) และคลังคำศัพท์ (Glossary) |
| ไฟล์ | Google Drive | ไฟล์งานแปล (โฟลเดอร์ละงาน), รูปโพสต์ข่าว |

## 1. เตรียม Google Drive

ระบบใช้ 2 โฟลเดอร์ใน Google Drive

| โฟลเดอร์ | ใช้ทำอะไร | สร้างอย่างไร | การแชร์ |
|---|---|---|---|
| `TransCOM – งานแปล` | ไฟล์ลูกค้า แยกโฟลเดอร์ละงาน (เช่น `TR-2569-0001 – ชื่อลูกค้า`) | **`setup()` สร้างให้อัตโนมัติ** ในขั้นตอนที่ 2.3 | **ห้ามแชร์** — ส่วนตัวเท่านั้น |
| `TransCOM – รูปข่าวสาร` | รูปโพสต์ข่าว/โปรโมชั่น ที่จะแสดงบนเว็บ | สร้างเอง: drive.google.com → **ใหม่** → **โฟลเดอร์ใหม่** | **ทุกคนที่มีลิงก์ → ผู้มีสิทธิ์อ่าน** |

วิธีตั้งการแชร์ของโฟลเดอร์รูปข่าว:
1. คลิกขวาที่โฟลเดอร์ `TransCOM – รูปข่าวสาร` → **แชร์** → **แชร์**
2. ที่ **การเข้าถึงทั่วไป** เลือก **ทุกคนที่มีลิงก์** และสิทธิ์ **ผู้มีสิทธิ์อ่าน** → **เสร็จสิ้น**
3. ไฟล์ที่อัปโหลดเข้าโฟลเดอร์นี้ภายหลังจะได้สิทธิ์เดียวกันอัตโนมัติ

> ⚠️ โฟลเดอร์ `TransCOM – งานแปล` มีเอกสารและสำเนาบัตรประชาชนของลูกค้า **อย่าแชร์แบบสาธารณะเด็ดขาด**
> ย้ายโฟลเดอร์นี้ไปไว้ที่อื่นใน Drive ได้ แต่ห้ามลบ — ถ้าลบ ระบบจะสร้างโฟลเดอร์ใหม่ให้เมื่อมีงานถัดไป

## 2. สร้าง Google Sheet และติดตั้ง Apps Script

### 2.1 สร้าง Google Sheet
1. เปิด <https://sheets.new> แล้วตั้งชื่อไฟล์ เช่น `TransCOM – ระบบหลังบ้าน`
2. เมนู **ไฟล์** → **การตั้งค่า** → แท็บ **ทั่วไป** → **เขตเวลา** เลือก **(GMT+07:00) Bangkok** → **บันทึกการตั้งค่า**
   (วันที่ของข่าวและโปรโมชั่นอ้างอิงเขตเวลานี้)
3. จะเก็บไฟล์ Sheet ไว้ในโฟลเดอร์ `TransCOM – งานแปล` ก็ได้ (ห้ามเก็บในโฟลเดอร์รูปข่าวที่แชร์สาธารณะ)

### 2.2 วางโค้ด Apps Script
1. ใน Sheet เมนู **ส่วนขยาย** → **Apps Script** (เปิดแท็บใหม่)
2. ตั้งชื่อโปรเจกต์ที่มุมซ้ายบน เช่น `TransCOM Backend`
3. ในไฟล์ `Code.gs` ลบโค้ดเดิมทั้งหมด
4. เปิดไฟล์ [`apps-script/Code.gs`](apps-script/Code.gs) ใน GitHub → กดปุ่ม **Copy raw file** (ไอคอนคัดลอกมุมขวาบนของไฟล์)
   แล้ววางลงใน `Code.gs` ของ Apps Script
5. กด **บันทึก** (ไอคอนแผ่นดิสก์ หรือ Ctrl+S)
6. ไอคอนเฟือง **การตั้งค่าโปรเจกต์** (แถบซ้าย) → **เขตเวลา** เลือก **(GMT+07:00) Bangkok**

### 2.3 รัน `setup()` ครั้งแรก
1. กลับไปที่ **ตัวแก้ไข** (ไอคอน `< >`) ที่แถบด้านบน เลือกฟังก์ชัน **`setup`** → กด **เรียกใช้**
2. ระบบจะขอสิทธิ์ → **ตรวจสอบสิทธิ์** → เลือกบัญชี Google
3. ถ้าขึ้นว่า **Google ยังไม่ได้ยืนยันแอปนี้** → กด **ขั้นสูง** → **ไปที่ TransCOM Backend (ไม่ปลอดภัย)**
   (เป็นปกติของสคริปต์ที่เราเขียนเอง) → **อนุญาต**
   สิทธิ์ที่ขอ: จัดการ Google Sheet นี้, ส่งอีเมลในนามของคุณ (รหัสเข้าสู่ระบบและแจ้งงาน),
   จัดการไฟล์ใน Google Drive (เก็บไฟล์งาน) และทำงานตามเวลาแม้คุณไม่ได้เปิดอยู่ (ลบข้อมูลตามกำหนดทุกวัน)
4. รอจนบันทึกการดำเนินการขึ้นว่า **ดำเนินการเสร็จสมบูรณ์**

`setup()` ทำให้ 3 อย่าง: สร้างชีต (รวมชีต **Dashboard** และ **Glossary**), สร้างโฟลเดอร์ `TransCOM – งานแปล` และตั้ง **ทริกเกอร์** 2 ตัว
(ดูได้ที่ไอคอนนาฬิกา **ทริกเกอร์** แถบซ้าย):
- `onJobEdit` — เมื่อเปลี่ยน **สถานะ** ในชีต Jobs ระบบส่งอีเมลแจ้งลูกค้า
- `purgeDueJobs` — ทุกวันตี 3 ลบไฟล์และข้อมูลส่วนบุคคลของงานที่ถึงกำหนด

**อีเมลแจ้งงานใหม่** ส่งไปที่บัญชี Google ที่รันสคริปต์ ถ้าต้องการให้ส่งไปที่อีเมลอื่น:
ไอคอนเฟือง **การตั้งค่าโปรเจกต์** → **คุณสมบัติของสคริปต์** → **เพิ่ม** → ชื่อ `PROVIDER_EMAIL` ค่า = อีเมลที่ต้องการ

กลับไปที่ Sheet จะเห็นชีตใหม่:

| ชีต | เนื้อหา |
|---|---|
| **Users** | บัญชีลูกค้า (สร้างอัตโนมัติเมื่อลูกค้าเข้าสู่ระบบครั้งแรก) |
| **Jobs** | งานแปลที่ลูกค้าส่งจากเว็บ 1 แถวต่องาน — คอลัมน์ **สถานะ** มี dropdown และสี (ดูข้อ 5.1) |
| **Promotions** | โปรโมชั่นบนหน้าแรก — มีแถวตัวอย่าง 1 แถว (ยังไม่ติ๊ก "แสดง") |
| **News** | ข่าวสารและประกาศ — มีแถวตัวอย่าง 1 แถว (ยังไม่ติ๊ก "แสดง") |
| **Dashboard** | ภาพรวมงาน คำนวณจากชีต Jobs อัตโนมัติ (ดูข้อ 5.5) — อยู่เป็นชีตแรก |
| **Glossary** | คลังคำศัพท์สำหรับแปล มีคำพื้นฐานเอกสารทะเบียนราษฎรให้แล้ว (ดูข้อ 5.6) |
| **Discounts** | ส่วนลดตามประเภทลูกค้าและขั้นสมาชิก — ตั้งค่าบนเว็บได้ (ดูข้อ 5.7) |
| `_sessions` | ซ่อนไว้ — ข้อมูลการเข้าสู่ระบบ (เก็บแบบเข้ารหัส) **ห้ามแก้ไขหรือลบ** |

> ห้ามเปลี่ยน **ชื่อชีต** และ **ข้อความหัวคอลัมน์** (แถวที่ 1) เพราะระบบใช้ชื่อเหล่านี้ค้นหาข้อมูล
> แต่สลับลำดับคอลัมน์ หรือเพิ่มคอลัมน์ใหม่ไว้ทางขวาได้

## 3. เผยแพร่เป็น Web App และเชื่อมกับเว็บ

1. ใน Apps Script กด **ทำให้ใช้งานได้** (Deploy) มุมขวาบน → **การทำให้ใช้งานได้รายการใหม่** (New deployment)
2. คลิกไอคอนเฟืองข้าง **เลือกประเภท** → **เว็บแอป** (Web app)
3. ตั้งค่า:
   - **คำอธิบาย:** `v1`
   - **เรียกใช้ในฐานะ (Execute as):** **ฉัน** (อีเมลของคุณ)
   - **ผู้ที่มีสิทธิ์เข้าถึง (Who has access):** **ทุกคน** (Anyone)
4. กด **ทำให้ใช้งานได้** → คัดลอก **URL ของเว็บแอป** ที่ลงท้ายด้วย `/exec`
5. ทดสอบ: วาง URL ในเบราว์เซอร์ ต้องเห็นข้อความ `{"ok":true,"service":"TransCOM"}`
6. นำ URL ไปใส่ในเว็บ — เลือกวิธีใดวิธีหนึ่ง
   - **ส่ง URL ให้ผู้พัฒนา** แล้วให้ใส่ให้ หรือ
   - **แก้เองบน GitHub:** เปิดไฟล์ [`js/config.js`](js/config.js) → ไอคอนดินสอ (Edit) → แก้บรรทัด
     ```js
     appsScriptUrl: "https://script.google.com/macros/s/xxxxxxxx/exec",
     ```
     → **Commit changes**

> "ทุกคน" หมายถึงหน้าเว็บของลูกค้าเรียกใช้ระบบได้โดยไม่ต้องล็อกอิน Google
> ลูกค้า **ไม่สามารถ** เปิดดู Sheet หรือแก้โค้ดได้ — ระบบตอบเฉพาะคำสั่งที่โค้ดอนุญาตเท่านั้น

## 4. ทดสอบระบบ

หลังใส่ URL ใน `config.js` และเว็บอัปเดตแล้ว (GitHub Pages ใช้เวลา 1–2 นาที):

| ทดสอบ | วิธี | ผลที่ควรได้ |
|---|---|---|
| ส่งงาน | หน้าเว็บ → **ส่งงานแปล** → กรอกข้อมูล แนบไฟล์ → **ส่งงานแปล** | ขึ้นเลขที่งาน `TR-2569-0001`, มีแถวใหม่ในชีต **Jobs**, โฟลเดอร์ใหม่ใน `TransCOM – งานแปล`, อีเมลถึงลูกค้าและถึงคุณ |
| อีเมลสถานะ | ในชีต Jobs เปลี่ยน **สถานะ** เป็น **ส่งใบเสนอราคาแล้ว** | อีเมลของลูกค้าได้รับข้อความแจ้ง |
| ติดตามงาน | หน้าเว็บ → **สั่งงาน → ติดตามงาน** → กรอกเลขที่งานและอีเมลที่ใช้ส่งงาน | เห็นสถานะ **ส่งใบเสนอราคาแล้ว** พร้อมขั้นตอนของงาน · ลองอีเมลอื่น ต้องขึ้น "ไม่พบงาน" |
| ภาพรวม | เปิดชีต **Dashboard** | ตัวเลขงานตามสถานะและประเภทตรงกับชีต Jobs |
| สมัคร/เข้าสู่ระบบ | หน้าเว็บ → **เข้าสู่ระบบ** → กรอกอีเมลของคุณ | ได้อีเมลรหัส 6 หลัก (ดูโฟลเดอร์สแปมด้วย) |
| ยืนยันรหัส | กรอกรหัส | เข้าหน้า **บัญชีของฉัน** และมีแถวใหม่ในชีต **Users** |
| ข้อมูลส่วนตัว | กรอกชื่อ เบอร์ → **บันทึกข้อมูล** | ข้อมูลขึ้นในชีต Users |
| กรอกฟอร์มอัตโนมัติ | ไปหน้า **ส่งงานแปล** | ชื่อ อีเมล เบอร์ ถูกกรอกให้ |
| ข่าวสาร | ติ๊ก **แสดง** ในชีต News 1 แถว | ภายใน 5 นาที โพสต์ขึ้นในหน้า **ข่าวสารและประกาศ** |
| ลบบัญชี | บัญชีของฉัน → **ลบบัญชี** | แถวในชีต Users หายไป |

## 5. การใช้งานประจำวัน

### 5.1 งานแปล (ชีต **Jobs**)

เมื่อลูกค้ากดส่งงานบนเว็บ:
1. ระบบสร้างเลขที่งานเรียงต่อกัน เช่น `TR-2569-0001` (ขึ้นปี พ.ศ. ใหม่จะเริ่ม 0001)
2. เก็บไฟล์ในโฟลเดอร์ของงานนั้น (ไฟล์บัตรของเอกสารทะเบียนราษฎรอยู่ในโฟลเดอร์ย่อยแยก)
3. เพิ่มแถวในชีต **Jobs** สถานะ **ได้รับงานแล้ว**
4. ส่งอีเมลยืนยันให้ลูกค้า และอีเมลแจ้ง **งานใหม่** พร้อมลิงก์โฟลเดอร์ให้คุณ

**เปลี่ยนสถานะในคอลัมน์ "สถานะ" → ลูกค้าได้รับอีเมลอัตโนมัติ** (ภาษาตามที่ลูกค้าใช้)

| สถานะ | อีเมลถึงลูกค้า |
|---|---|
| ได้รับงานแล้ว | (ส่งไปแล้วตอนรับงาน) |
| ส่งใบเสนอราคาแล้ว | แจ้งให้ตรวจอีเมลใบเสนอราคา — **ส่งใบเสนอราคาให้ลูกค้าเองทางอีเมลก่อน** (ระบบใบเสนอราคาอัตโนมัติอยู่ในแผนถัดไป) |
| ชำระเงินแล้ว | แจ้งว่าได้รับเงินและเริ่มแปล |
| กำลังแปล | แจ้งว่าอยู่ระหว่างแปล |
| ส่งมอบแล้ว | แจ้งส่งมอบ + ปุ่ม **ยืนยันว่างานแปลถูกต้อง** — **ส่งไฟล์งานแปลให้ลูกค้าเองทางอีเมลก่อน** |
| ยกเลิก | แจ้งว่างานถูกยกเลิก |

**การลบข้อมูลอัตโนมัติ** (ตามนโยบายความเป็นส่วนตัว):
- เมื่อเปลี่ยนเป็น **ส่งมอบแล้ว** ระบบใส่ **ส่งมอบเมื่อ** และ **กำหนดลบข้อมูล** = 90 วันหลังส่งมอบ
- เอกสารทะเบียนราษฎร: เมื่อลูกค้ากดยืนยันในอีเมล ระบบใส่ **ลูกค้ายืนยันความถูกต้องเมื่อ** และเลื่อน **กำหนดลบข้อมูล** เป็น 15 วันหลังยืนยัน
- ทุกวันตี 3 งานที่ถึงกำหนด: โฟลเดอร์ไฟล์ย้ายไปถังขยะของ Drive (กู้คืนได้ 30 วัน) และล้างชื่อ อีเมล เบอร์ ที่อยู่ หมายเหตุ
  เหลือเลขที่งาน วันที่ ประเภท และสถานะไว้เป็นสถิติ — คอลัมน์ **ลบข้อมูลแล้วเมื่อ** บอกวันที่ลบ
- ต้องการเลื่อนหรือยกเลิกการลบงานใด: แก้หรือลบค่าในคอลัมน์ **กำหนดลบข้อมูล** ของงานนั้น

> - **ห้ามลบแถว** ในชีต Jobs — ประวัติงานของลูกค้าและเลขที่งานอ้างอิงจากแถวเหล่านี้
> - คอลัมน์ **ประเภทเอกสาร** และ **คู่ภาษา** เก็บเป็นรหัส: `civil` ทะเบียนราษฎร · `official` ราชการ · `academic` การศึกษา ·
>   `business` ธุรกิจ/สัญญา · `other` เอกสารอื่น ๆ · `th-en` ไทย→อังกฤษ · `en-th` อังกฤษ→ไทย
> - แถวที่ **สถานะว่าง** คือการอัปโหลดที่ยังไม่เสร็จ (ลูกค้าปิดหน้าเว็บกลางคัน) — ไม่มีอีเมลแจ้ง ลบแถวนั้นได้

### 5.1.1 ลูกค้าติดตามงานเอง (หน้า **ติดตามงาน**)

ลูกค้ากรอก **เลขที่งาน** และ **อีเมลที่ใช้ส่งงาน** แล้วเห็นสถานะล่าสุดจากคอลัมน์ **สถานะ** ทันที
(ไม่ต้องเข้าสู่ระบบ) — คุณไม่ต้องทำอะไรเพิ่ม แค่เปลี่ยนสถานะในชีตตามปกติ

- หน้าเว็บแสดงเฉพาะ: สถานะ, ขั้นตอน 5 ขั้น (ได้รับงาน → ใบเสนอราคา → ชำระเงิน → กำลังแปล → ส่งมอบ),
  ประเภทเอกสาร, คู่ภาษา, จำนวนหน้า, วันที่ส่งงาน, วันที่ต้องการรับงาน, วันที่ส่งมอบ
  และวันที่ลูกค้ายืนยันความถูกต้อง — **ไม่แสดง** ชื่อ ที่อยู่ เบอร์ หมายเหตุ หรือไฟล์
- ถ้าเลขที่งานหรืออีเมลไม่ตรงกัน, อัปโหลดยังไม่เสร็จ หรือข้อมูลงานถูกลบแล้ว จะขึ้นข้อความเดียวกันว่า **ไม่พบงาน**
  (คนอื่นจึงเดาข้อมูลจากข้อความไม่ได้)
- ถ้าพิมพ์สถานะเองที่ไม่อยู่ใน dropdown (เช่น "รอเอกสารเพิ่ม") หน้าเว็บจะแสดงว่า **กำลังดำเนินการ**
- ลูกค้าที่เข้าสู่ระบบไว้ ระบบกรอกอีเมลในหน้าติดตามงานให้ และเห็นสถานะทุกงานในหน้า **บัญชีของฉัน** ด้วย

### 5.4 บัญชีลูกค้า (ชีต **Users**)

- ลูกค้าเข้าสู่ระบบด้วยรหัสทางอีเมลเท่านั้น ไม่มีรหัสผ่านให้รีเซ็ต

### 5.6 คลังคำศัพท์ (ชีต **Glossary**)

รายการคำแปลที่ใช้ประจำ เพื่อให้ชื่อเอกสาร หน่วยงาน สถานที่ และคำนำหน้าชื่อแปลเหมือนกันทุกงาน
(สำหรับผู้แปลเท่านั้น ลูกค้าไม่เห็น)

- คอลัมน์: **คำศัพท์ (ไทย)** · **English** · **หมวด** · **หมายเหตุ / ที่มา**
- `setup` ใส่คำพื้นฐานของเอกสารทะเบียนราษฎรให้ครั้งแรกครั้งเดียว — **ตรวจทานและแก้ให้ตรงกับแนวที่คุณใช้**
  แล้วเพิ่มคำใหม่ได้เรื่อย ๆ (รัน `setup` ซ้ำ คำที่คุณเพิ่มหรือแก้ไม่หาย)
- ใช้ตัวกรอง (**ข้อมูล → สร้างตัวกรอง**) เพื่อดูเฉพาะหมวด หรือกด Ctrl+F ค้นหาคำ

### 5.7 หน้าจัดการบนเว็บ (บัญชีของฉัน)

เข้าสู่ระบบที่ **www.prathaitranslation.com → บัญชีของฉัน** ด้วยรหัสทางอีเมลเหมือนลูกค้า
ระบบดูบทบาทจากชีต Users แล้วแสดงเมนูตามบทบาท — ทุกคำสั่งตรวจสิทธิ์ที่เซิร์ฟเวอร์ แก้หน้าเว็บก็เข้าข้อมูลคนอื่นไม่ได้

**ใครเป็นผู้ดูแลระบบ (Admin)**
- อีเมลที่รับแจ้งงานใหม่ (`PROVIDER_EMAIL` หรือบัญชีที่ติดตั้งสคริปต์ — ปัจจุบันคือ contact@prathaitranslation.com) **เป็น Admin เสมอ**
- เพิ่ม Admin หรือพนักงานคนอื่นได้ที่เมนู **ผู้ใช้และบทบาท** → ใส่อีเมล Google ของคนนั้น → **เพิ่ม**
  แล้วให้เขาเข้าสู่ระบบด้วยอีเมลนั้น
- (ทางเลือก) Admin ถาวรเพิ่มเติม: คุณสมบัติของสคริปต์ `ADMIN_EMAILS` = อีเมลคั่นด้วยจุลภาค

| บทบาท | เห็นและทำอะไรได้ |
|---|---|
| **ลูกค้า** | ภาพรวมงาน · ออเดอร์ (กำลังดำเนินการ / ปิดงานแล้ว / คำขอยกเลิก) · ขั้นตอนของงาน · **ดาวน์โหลดไฟล์งานแปล** หลังส่งมอบ · **ขอยกเลิกงาน** (ก่อนชำระเงิน) · แก้ไขโปรไฟล์ · ลบบัญชี — **ไม่เห็นว่าใครเป็นผู้แปล** |
| **พนักงาน** (รวมนักแปล) | เฉพาะงานที่ Admin มอบหมาย · ดาวน์โหลดไฟล์ต้นฉบับและสำเนาบัตร · **อัปโหลดไฟล์งานแปล** · กด **เริ่มแปล** (ลูกค้าได้อีเมล "กำลังแปล") · กด **แปลเสร็จ ส่งตรวจ** (Admin ได้อีเมล) · บันทึกภายใน — **ไม่เห็นชื่อ อีเมล เบอร์ ที่อยู่ของลูกค้า** |
| **ผู้ดูแลระบบ** | ทุกอย่างของพนักงาน + **ภาพรวม** (งานค้าง ใกล้กำหนด เลยกำหนด รอตรวจ คำขอยกเลิก ยังไม่มอบหมาย) · **งานทั้งหมด** (ค้นหา กรอง) · มอบหมายพนักงาน · เปลี่ยนสถานะ (ส่งอีเมลลูกค้าเหมือนแก้ในชีต) · อนุมัติ/ปฏิเสธคำขอยกเลิก · **ผู้ใช้และบทบาท** · **ส่วนลด** |

**ขั้นตอนงานปกติบนเว็บ**
1. ลูกค้าส่งงาน → Admin เปิด **งานทั้งหมด** → เลือกงาน → เปลี่ยนสถานะเป็น **ส่งใบเสนอราคาแล้ว** (ส่งใบเสนอราคาทางอีเมลเองก่อน จนกว่าจะเปิดระบบใบเสนอราคา)
2. ลูกค้าชำระเงิน → สถานะ **ชำระเงินแล้ว** → เลือก **ผู้รับผิดชอบ** → **บันทึกข้อมูล** (พนักงานได้อีเมลแจ้ง)
3. พนักงานเปิด **งานของฉัน** → ดาวน์โหลดต้นฉบับ → **เริ่มแปล** → อัปโหลดไฟล์งานแปล → **แปลเสร็จ ส่งตรวจ**
4. Admin ได้อีเมล "แปลเสร็จ รอตรวจ" → เปิดงาน → ตรวจไฟล์ → สถานะ **ส่งมอบแล้ว** → ลูกค้าได้อีเมลพร้อมปุ่มยืนยัน และดาวน์โหลดไฟล์ได้ในบัญชีของตัวเอง

- ไฟล์งานแปลอยู่ในโฟลเดอร์ย่อย `งานแปล (ส่งลูกค้า)` ในโฟลเดอร์ของงาน — ลบตามกำหนดพร้อมไฟล์อื่น
- ทุกการกระทำ (มอบหมาย เปลี่ยนสถานะ อัปโหลด) บันทึกในคอลัมน์ **บันทึกภายใน** พร้อมเวลาและอีเมลผู้ทำ
- ยังจัดการงานในชีต Jobs ได้เหมือนเดิม — เว็บกับชีตใช้ข้อมูลชุดเดียวกัน

**ส่วนลด** (เมนู **ส่วนลด**): ตั้ง % ส่วนลดของแต่ละประเภทลูกค้า (ทั่วไป · องค์กร/บริษัท · เอเจนซี่/ตัวแทน · นักเรียน/นักศึกษา)
และขั้นสมาชิกตามยอดใช้จ่าย (เช่น Gold: ยอดสะสม 20,000 บาท ลด 7%) — บันทึกไว้ในชีต **Discounts**
**ระบบจะเริ่มคำนวณส่วนลดบนใบเสนอราคาเมื่อเปิดระบบใบเสนอราคาและชำระเงิน (เฟสถัดไป)** พร้อมโค้ดส่วนลดตามช่วงเวลา

## 6. อัปเดตโค้ด Apps Script ภายหลัง

เมื่อมีโค้ด `Code.gs` เวอร์ชันใหม่:
1. วางโค้ดใหม่ทับใน Apps Script → **บันทึก**
2. ถ้ามีชีตหรือคอลัมน์ใหม่ ให้รัน **`setup`** อีกครั้ง (ข้อมูลเดิมไม่หาย — คอลัมน์ใหม่จะต่อท้ายทางขวา)
   - อัปเดตเพื่อเปิด **หน้าจัดการบนเว็บ (ข้อ 5.7)**: **ต้องรัน `setup`** เพื่อเพิ่มคอลัมน์ บทบาท / ประเภทลูกค้า / ผู้รับผิดชอบ ฯลฯ และชีต Discounts
3. **ทำให้ใช้งานได้** → **จัดการการทำให้ใช้งานได้** → ไอคอนดินสอ (แก้ไข) →
   **เวอร์ชัน:** เลือก **เวอร์ชันใหม่** → **ทำให้ใช้งานได้**

> ⚠️ อย่ากด **การทำให้ใช้งานได้รายการใหม่** ซ้ำ — จะได้ URL ใหม่ และต้องแก้ `config.js` ใหม่
> การแก้ไขผ่าน **จัดการการทำให้ใช้งานได้** จะใช้ URL เดิม

## 7. เปิดเว็บด้วย GitHub Pages และโดเมน www.prathaitranslation.com

เว็บเปิดตรงจาก GitHub Pages (ฟรี) ผูกกับโดเมนของเรา โดเมนดูแลที่ **Cloudflare**
แถบ URL จะเปลี่ยนตามหน้า เช่น `www.prathaitranslation.com/#pricing` — คัดลอกส่งให้ลูกค้าเปิดหน้านั้นตรง ๆ ได้

### 7.1 เปิด GitHub Pages (ทำครั้งเดียว — ทำแล้ว)
1. repository ต้องเป็น **Public** (GitHub Pages ฟรีใช้ได้เฉพาะ repo สาธารณะ — ในโค้ดไม่มีข้อมูลลับ)
2. รวมงานล่าสุดเข้า branch `main` (merge Pull Request)
3. **Settings** → **Pages** → **Source:** `Deploy from a branch` → **Branch:** `main` / `/ (root)` → **Save**
4. รอ 1–2 นาที เว็บเปิดได้ที่ <https://transcomls.github.io/TransCOM-Landing-page/>

ทุกครั้งที่ `main` เปลี่ยน (เช่น แก้ `js/config.js` บน GitHub) เว็บอัปเดตเองภายใน 1–2 นาที

### 7.2 ผูกโดเมนที่ Cloudflare
1. เข้า <https://dash.cloudflare.com> → เลือกโดเมน `prathaitranslation.com` → **DNS** → **Records**
2. **www:** ถ้ามีระเบียน `www` เดิม (เช่นของ Google Sites ที่ชี้ไป `ghs.googlehosted.com`) กด **Edit** ถ้าไม่มี กด **Add record** แล้วตั้งเป็น

   | Type | Name | Target | Proxy status |
   |---|---|---|---|
   | `CNAME` | `www` | `transcomls.github.io` | **DNS only** (เมฆสีเทา) |

3. **โดเมนเปล่า** (`prathaitranslation.com` ไม่มี www — ให้พาไปที่ www อัตโนมัติ): เพิ่มระเบียน `A` 4 รายการ
   Name `@` · Proxy status **DNS only** · ค่า `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   (ถ้ามีระเบียน `A`/`AAAA`/`CNAME` ของ `@` เดิมอยู่ ให้ลบหรือแก้แทน — ระเบียนชื่อเดียวกันซ้อนกันไม่ได้)
4. ⚠️ **ห้ามแก้หรือลบระเบียน `MX` และ `TXT`** — เป็นของอีเมล `contact@prathaitranslation.com` และการยืนยันโดเมนกับ Google
5. ⚠️ ต้องเป็น **DNS only** (เมฆสีเทา) — ถ้าเป็นเมฆสีส้ม GitHub ออกใบรับรอง HTTPS ไม่ได้ และเว็บอาจเปิดไม่ขึ้น

### 7.3 ใส่โดเมนใน GitHub
1. **Settings** → **Pages** → **Custom domain** → พิมพ์ `www.prathaitranslation.com` → **Save**
2. รอให้ขึ้น ✅ **DNS check successful** (ปกติไม่กี่นาที บางครั้งถึง 24 ชั่วโมง)
3. ติ๊ก **Enforce HTTPS** (ถ้ายังติ๊กไม่ได้ แปลว่ากำลังออกใบรับรอง — รอแล้วกลับมาติ๊กอีกครั้ง)
4. GitHub จะเพิ่มไฟล์ `CNAME` ใน repo ให้เอง — **ห้ามลบไฟล์นี้** เพราะเป็นตัวบอกว่าเว็บใช้โดเมนอะไร
5. (แนะนำ) กันคนอื่นแอบผูกโดเมนนี้: หน้าองค์กร TransCOMLS → **Settings** → **Pages** → **Add a domain** →
   `prathaitranslation.com` → เพิ่มระเบียน `TXT` ที่ GitHub ให้มาใน Cloudflare → **Verify**

ลิงก์เดิม `transcomls.github.io/TransCOM-Landing-page/` จะพาไปที่ `www.prathaitranslation.com` อัตโนมัติ

### 7.4 เลิกใช้ Google Sites (หลังข้อ 7.3 เปิดได้แล้ว)
1. เปิด `https://www.prathaitranslation.com` ให้แน่ใจว่าเห็นเว็บใหม่ (ลองทั้งคอมพิวเตอร์และมือถือ)
2. ใน Google Sites → ไอคอนเฟือง **การตั้งค่า** → **โดเมนที่กำหนดเอง** → ลบ `www.prathaitranslation.com`
   (เว็บ Google Sites ยังอยู่ที่ลิงก์ `sites.google.com/...` — จะเก็บไว้หรือลบทิ้งก็ได้)
3. อัปเดตลิงก์ที่ใช้ภายนอก เช่น ข้อความต้อนรับใน LINE OA, Google Business Profile, นามบัตร → `https://www.prathaitranslation.com`

## 8. ตั้งค่าที่แก้ได้ใน `js/config.js`

แก้บน GitHub ได้โดยตรง (เปิดไฟล์ → ไอคอนดินสอ → **Commit changes**) — ค่าในวงเล็บเหลี่ยม `[ ]` คือค่าที่ยังต้องกรอก

| ค่า | ความหมาย |
|---|---|
| `appsScriptUrl` | URL ของ Web App (ขั้นตอนที่ 3) |
| `contact` | อีเมล เบอร์โทร เวลาทำการ · LINE OA `@transcomls` (`lineId`, `lineUrl`) · `showLine: false` ซ่อนปุ่ม LINE ทั้งเว็บ |
| `categories` | ประเภทเอกสารและราคาต่อหน้า `[ต่ำสุด, สูงสุด]` แบบปกติ/ด่วน · ถ้า **เพิ่มประเภทใหม่** ให้เพิ่มชื่อใน `CATEGORY_NAMES` ตอนต้นไฟล์ `Code.gs` ด้วย (ใช้ในอีเมลและ Dashboard) |
| `certificationFee` / `shippingFee` | ค่ารับรองคำแปล / ค่าจัดส่งฉบับจริง (ต่องาน) |
| `turnaround` | ระยะเวลางานปกติ/ด่วน (วันทำการ) |
| `promotions` / `news` | โปรโมชั่นและข่าว (ใช้เมื่อชีตยังไม่มีแถวที่ติ๊ก "แสดง") · `active: false` = ซ่อน |
| `popularDocs` | ปุ่มลัด "เอกสารที่แปลบ่อย" บนหน้าแรก |
| `revisionDays` / `retentionDays` / `idRetentionDays` | ระยะเวลาแก้งาน / เก็บข้อมูล / ลบข้อมูลเอกสารทะเบียนราษฎร |

## 9. ความปลอดภัยและข้อจำกัด

- **ห้ามแชร์ Google Sheet** ให้คนนอก — มีข้อมูลส่วนบุคคลของลูกค้า
- **คุณสมบัติของสคริปต์** (การตั้งค่าโปรเจกต์ → คุณสมบัติของสคริปต์) — ระบบสร้างให้เอง:
  - `PEPPER` — **ห้ามลบ** ถ้าลบ ลูกค้าทุกคนจะถูกออกจากระบบ และลิงก์ยืนยันในอีเมลเก่าจะใช้ไม่ได้
  - `JOBS_FOLDER_ID` — รหัสโฟลเดอร์ `TransCOM – งานแปล`
  - `SEQ_2569` (ตามปี พ.ศ.) — เลขที่งานล่าสุดของปี **ห้ามแก้ให้น้อยลง** เลขที่งานจะซ้ำ
  - `PROVIDER_EMAIL` — (ใส่เองถ้าต้องการ) อีเมลที่รับแจ้งงานใหม่
- รหัสเข้าสู่ระบบหมดอายุใน 10 นาที กรอกผิดได้ 5 ครั้ง ขอใหม่ได้ทุก 60 วินาที ไม่เกิน 5 ครั้งต่อชั่วโมง
- รหัสและข้อมูลการเข้าสู่ระบบเก็บแบบเข้ารหัสทางเดียว (hash) ไม่มีใครอ่านค่าจริงได้ รวมถึงผู้ดูแล
- **โควตาอีเมลของ Google:** บัญชี Gmail ทั่วไปส่งได้ประมาณ **100 ฉบับ/วัน** · Google Workspace ประมาณ **1,500 ฉบับ/วัน**
  — 1 งานใช้ 2 ฉบับตอนรับงาน และ 1 ฉบับต่อการเปลี่ยนสถานะ (นับรวมอีเมลรหัสเข้าสู่ระบบด้วย)
- กันสแปม: รับงานได้ไม่เกิน 5 งานต่ออีเมลต่อชั่วโมง ไม่เกิน 10 ไฟล์ต่องาน ไฟล์ละไม่เกิน 10 MB
- ติดตามงาน: ตรวจได้ไม่เกิน 30 ครั้งต่ออีเมลต่อชั่วโมง และถ้ามีการกรอกผิดรวมกันเกิน 300 ครั้งในชั่วโมงเดียว ระบบพักการตรวจไว้ชั่วคราว
  ตอบกลับเฉพาะสถานะและวันที่ ไม่มีข้อมูลส่วนบุคคลหรือไฟล์
- โฟลเดอร์ `TransCOM – งานแปล` ต้องเป็นส่วนตัวเสมอ — แชร์สาธารณะได้เฉพาะโฟลเดอร์รูปข่าว

## 10. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| หน้า **บัญชีของฉัน** ขึ้นว่า "ยังไม่เปิดใช้งาน" | ยังไม่ได้ใส่ `appsScriptUrl` ใน `config.js` หรือเว็บยังไม่อัปเดต (รอ 1–2 นาที แล้วรีเฟรช) |
| กดรับรหัสแล้วขึ้น "เชื่อมต่อไม่ได้" | URL ผิด (ต้องลงท้าย `/exec`) หรือไม่ได้ตั้ง **ผู้ที่มีสิทธิ์เข้าถึง: ทุกคน** |
| ไม่ได้รับอีเมลรหัส | ดูโฟลเดอร์สแปม · เกินโควตาอีเมลรายวัน · ใน Apps Script ดูเมนู **การดำเนินการ** ว่ามีข้อผิดพลาดหรือไม่ |
| แก้โค้ดแล้วเว็บยังทำงานแบบเดิม | ยังไม่ได้ทำ **จัดการการทำให้ใช้งานได้ → เวอร์ชันใหม่** (ขั้นตอนที่ 6) |
| แก้ชีต News/Promotions แล้วเว็บไม่เปลี่ยน | รอ 5 นาที · ตรวจว่าติ๊ก **แสดง** แล้ว · วันที่เริ่มต้องไม่อยู่ในอนาคต |
| รูปโพสต์ไม่ขึ้น (ขึ้นภาพปกแทน) | รูปยังไม่ได้แชร์ **ทุกคนที่มีลิงก์** · ลิงก์ต้องขึ้นต้นด้วย `https://` |
| `setup` ขึ้นข้อผิดพลาดเรื่องสิทธิ์ | รัน `setup` ใหม่แล้วกด **อนุญาต** ให้ครบทุกข้อ |
| ลูกค้าส่งงานไม่สำเร็จ ขึ้น "เชื่อมต่อไม่ได้" | ให้ลูกค้ากดส่งอีกครั้ง ระบบส่งต่อจากไฟล์ที่ค้าง (ภายใน 6 ชั่วโมง) โดยไม่สร้างงานซ้ำ |
| เปลี่ยนสถานะแล้วลูกค้าไม่ได้อีเมล | ตรวจว่ามีทริกเกอร์ `onJobEdit` (ไอคอนนาฬิกา) ถ้าไม่มี ให้รัน `setup` อีกครั้ง · ดูเมนู **การดำเนินการ** |
| หน้าบัญชีขึ้น "บัญชีนี้ไม่มีสิทธิ์ทำรายการนี้" | บทบาทในชีต Users ไม่ถูกต้อง หรือยังไม่ได้รัน `setup` หลังอัปเดตโค้ด · Admin ตั้งบทบาทได้ที่ **ผู้ใช้และบทบาท** |
| พนักงานไม่เห็นงาน | Admin ยังไม่ได้เลือก **ผู้รับผิดชอบ** ในงานนั้น หรือพนักงานเข้าสู่ระบบด้วยอีเมลคนละอันกับที่เพิ่มไว้ |
| ไม่ได้รับอีเมลแจ้งงานใหม่ | ตรวจ `PROVIDER_EMAIL` ในคุณสมบัติของสคริปต์ · ดูโฟลเดอร์สแปม · โควตาอีเมลรายวัน |
| ลูกค้าติดตามงานแล้วขึ้น "ไม่พบงาน" | ต้องใช้ **อีเมลเดียวกับที่ส่งงาน** · เลขที่งานรูปแบบ `TR-2569-0001` · สถานะของงานต้องไม่ว่าง · งานที่ลบข้อมูลแล้วจะค้นไม่พบ |
| ชีต Dashboard ขึ้น `#N/A` หรือ `#REF!` | หัวคอลัมน์ในชีต Jobs ถูกเปลี่ยนชื่อ — แก้กลับให้ตรงเดิม แล้วรัน `setup` อีกครั้ง |
| วันที่ในข่าวคลาดไป 1 วัน | ตั้งเขตเวลาของ Sheet และโปรเจกต์ Apps Script เป็น Bangkok (ขั้นตอน 2.1 และ 2.2) |
